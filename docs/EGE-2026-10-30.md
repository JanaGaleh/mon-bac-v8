## Code livré

- Catalogue public interrogé dans Supabase, recherche et filtres ; indisponibilité explicite si aucun dossier validé.
- Compte e-mail/mot de passe, inscription avec retour de confirmation, demande de récupération et nouveau mot de passe. Les redirections et l’envoi d’e-mails restent à vérifier pour le domaine final.
- Profil EGE distinct de MON BAC, identité, établissement, classe, WhatsApp.
- Confirmation et réservation dans une transaction serveur, attribution unique par établissement normalisé et année ; commande répétée idempotente et prix fixé côté serveur.
- Suivi de commande, déclaration de référence et lien WhatsApp à ouvrir volontairement ; aucune confirmation automatique du paiement.
- Téléchargement via la fonction Edge existante, uniquement après paiement et livraison ; lien signé 60 secondes, aucun stockage public des Word.
- Corrections demandées pour le dossier livré du demandeur, pendant les 7 jours après livraison.
- Administration avec comptages réels, décisions de paiement et dépôt initial du Word personnalisé sans écrasement.
- Manifeste et worker propres à EGE, cache limité aux fichiers statiques ; le catalogue et les données privées nécessitent Internet.

## Base : migration appliquée

`20261030140008_ege_parcours_et_securite.sql` est une migration **déjà appliquée**, dont la version provient de l’historique distant. Elle dépend des migrations EGE préexistantes dans Supabase, qui ne sont pas toutes présentes dans ce dépôt : ne pas lancer un reset de la base à partir de ce seul dépôt.

Elle corrige le format du téléphone, la règle de correction qui n’était pas liée au dossier demandé, le verrouillage de la problématique, et les attributions basées désormais sur l’établissement figé lors de la confirmation. Elle retire les permissions inutiles, dont TRUNCATE qui ne dépend pas de RLS, et garde privés les chemins des documents. Une publication et une réservation vérifient les objets Storage. Les commandes des candidats libres restent bloquées jusqu’à définition de leurs règles ; leur profil peut être renseigné.

Les opérations privilégiées vérifient `auth.uid()` et les droits en base, avec `search_path` vide. Le trigger de présence des objets est dans le schéma non exposé `ege_private`. Le paiement reste exclusivement validé par un administrateur après encaissement.

## Vérification

`tests/ege-security.sql` a réussi sur Supabase avec `ROLLBACK` : catalogue public, absence de lecture du dossier B par A, refus d’une correction sur un dossier non livré ou appartenant à B, correction sur le bon dossier, impossibilité de téléchargement sans livraison Word, maximum de mots effectif, verrouillage, publication sans fichier refusée, prix serveur, idempotence et unicité par établissement. Le test d’attribution utilise des **métadonnées Storage temporaires** ; il ne certifie ni un transfert de fichier ni le contenu d’un DOCX.

Les tests métier et syntaxiques sont passés localement. La suite CI GitHub est passée, dont le parcours DOM EGE avec API simulée (connexion, profil, commande via RPC, protection XSS, indisponibilité et effacement privé). Des tests Chromium en largeurs 390 et 1440 sont fournis séparément dans le workflow ; leur résultat doit être vérifié avant réception. Les paiements et comptes réels, les e-mails et les téléphones physiques ne sont pas couverts par ces simulations.

## Travaux bloquant la réception complète

1. Fournir le modèle Nassima et l’archive Word mentionnés dans le cahier des charges, puis contrôler les sources, le contenu et le rendu A4 par lots. Aucun de ces fichiers n’est dans ce dépôt ni dans Storage.
2. Construire l’import ZIP contrôlé, ses checksums/reprises, les rapports de qualité, la démonstration filigranée et la publication versionnée. Le dépôt initial d’un Word de livraison ne remplace pas ces outils de production documentaire.
3. Compléter le traitement des corrections et ses décisions/journal ; l’élève peut déposer sa demande et l’administration la consulter, mais ce changement n’ajoute pas encore le workflow de réponse et de nouvelle version livrée.
4. Finaliser les conditions commerciales et les informations de conservation des données, les coordonnées marchandes, les règles candidats libres et les arbitrages du cahier des charges. Le maximum technique est actuellement de 28 mots ; le tarif binôme existant est conservé.
5. Vérifier les redirections Auth, le parcours réel paiement/livraison, les liens signés et l’installation sur appareils physiques.

## Hébergement

Le dossier statique est prévu pour `/ege/` ; Vercel redirige `/ege` vers `/ege/`. Il fonctionne aussi sous le sous-chemin GitHub Pages du dépôt. La carte EGE est ajoutée au registre de navigation.

La connexion Vercel consultée voit trois projets du portail `janagaleh-plateform`, mais aucun projet `mon-bac-v8`. Le dépôt MON BAC n’apparaît pas parmi ses dépôts Git autorisés. Aucun domaine `janagaleh.com` n’est affiché sur les trois projets visibles ; le CNAME existant de MON BAC est `monbac.janagaleh.com`. Le déploiement sur l’adresse cible ne peut donc pas être déclaré fait. Il faut autoriser le dépôt dans l’intégration GitHub de Vercel et identifier/configurer l’hébergement du domaine final. Aucun DNS ni rattachement de domaine n’a été changé.

Les conseillers Supabase signalent toujours des points préexistants (tables fermées sans politique, extension dans public, protection contre les mots de passe compromis désactivée, index manquants). Les fonctions métier SECURITY DEFINER sont intentionnelles et contrôlent leur appelant ; les avis ne sont pas tous des vulnérabilités.
